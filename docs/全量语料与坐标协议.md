# 全量语料、真实坐标与图条件注意力

这份文档记录 2026-11-21 这一轮改造：**把"架构支持"变成"数据真的走到那条路径上"**，
以及由此新增的两个训练组件。所有数字要么来自本地实测，要么明确标为待跑。

## 一、上一版的实际问题

`model.py` 里一直有坐标编码：

```python
self.coordinates = nn.Linear(3, d, bias=False)
coord = self.coordinates(batch.coords.masked_fill(~batch.coord_valid[..., None], 0))
```

但预处理写的是：

```python
coords=np.zeros((len(channel_names), 3), np.float32),
coord_valid=np.zeros(len(channel_names), bool),
```

实测确认（`mi-development-v1` 任取一个 npz）：

```
x.shape=(64, 560)  coord_valid 之和=0  |coords| 最大值=0.0
```

也就是说 **`nn.Linear(3, d)` 的输入恒为零向量，坐标分支从未被激活**。
README 里"3D 电极坐标嵌入"这句话在代码上成立、在数据上不成立——这是本轮首先要修的。

## 二、坐标从哪来

新增 `src/eeg_mime_foundation/montage.py`：

| 布局 | 解析方式 | 结果 |
|---|---|---|
| EEGMMIDB 64 导 | MNE `standard_1020` 模板按名字精确匹配 | **64/64 解析成功** |
| 睡眠双极 `Fpz-Cz` / `Pz-Oz` | 取两电极中点 | 2/2 |
| 未收录名字 | 保留 0 并把 `valid` 置 False，不猜 | 由 ingest 拒绝（解析率 <90% 直接报错） |

坐标系：MNE 头坐标，原点在头中心，+x 右、+y 前、+z 上，单位米。
几何自检：C3–C4 间距 0.133 m，全导联最大间距 0.208 m（头表直径量级），测试固化为
`tests/test_montage_coordinates.py`。

## 四、图条件注意力（`model.graph=true`）

原 `FactorBlock` 的空间注意力是纯内容驱动的：C3 和 O1 的 token 与 C3 和 C4 的 token
走同一套 `QK^T`，电极的相对位置只通过输入时的坐标嵌入间接影响。这解释了一个旧结论：

> 结构化移除（感觉运动区 8 导，BA 0.5288）与随机移除 8 导（0.5390）几乎等价，
> 说明模型没有真正利用电极拓扑。

`GraphBlock` 在空间注意力上加一个**距离决定的加性偏置**：

1. 成对距离 `d_ij = ||p_i - p_j||`（米）；
2. 高斯核展开 `exp(-(d_ij - c_k)^2 / 2σ_k^2)`，核中心 `c_k` 在 0.01–0.16 m 均匀铺开，宽度可学；
3. 线性映射到 `heads` 维，得到 `[B, H, C, C]` 的偏置加到 `QK^T` 上；
4. 偏置权重**零初始化**——训练起点与普通 attention 完全等价，先验只作为可学增量进入。

无效导联（`coord_valid=False`）对应的偏置项强制为 0，不引入虚构位置。

已验证的结构性质（`tests/test_graph_bias.py`）：

- 零初始化时偏置恒为 0；
- 尾部填充通道不改变输出（Δ < 1e-5）；
- **通道置换等变**：信号/ID/坐标同步打乱后输出不变（atol 1e-4），证明拓扑确实由坐标而非列序决定；
- 距离改变时偏置随之改变且保持对称；
- 缺坐标的通道偏置为 0。

## 五、导联丢弃增广（`training.channel_dropout`）

T1 的实测结论是"导联越少越差，8 导掉 13 个百分点"。既然部署侧一定会遇到更稀疏的帽子，
训练时就让模型见到：按概率整列屏蔽通道（改 `valid`，不改 ID 与坐标），每样本至少留 1 个通道，
验证集不增广。它和 `graph` 是一对：图偏置告诉模型"电极在哪"，丢弃增广逼模型"少了电极也要扛住"。

## 六、评测协议

`scripts/run_grouped_cv.py`：被试分组 K 折（默认 10 折），清单里 `split=="test"` 的被试整折排除。
选它的原因很直接：留一法在 109 名被试上要跑 109 折，成本不可接受。

```bash
python scripts/download_corpora.py --dataset eegmmidb --root D:/wyu-bci-data --jobs 16
python scripts/prepare_real_data.py ingest --dataset mi --root D:/wyu-bci-data --scope corpus
python scripts/run_grouped_cv.py --name cv-fusion --arch fusion \
    --manifest D:/wyu-bci-data/processed/corpus/mi-corpus-v1/manifest.json \
    --base-config configs/mi_corpus_supervised.json --folds 10 --epochs 40
```

三组对照（**待跑**，本轮不做，因为单组预算在小时级）：

| 组 | 参数 | 想回答的问题 |
|---|---|---|
| A 基线 | `--arch fusion` | 全量语料下 fusion 的实际水平 |
| B 图偏置 | 加 `--graph` | 显式拓扑先验是否强于隐式坐标嵌入 |
| C 图偏置 + 丢弃 | 加 `--graph --channel-dropout 0.3` | 导联稀疏时是否比 A 更稳 |

判读口径：只有 B/A、C/A 的差值超过折间标准差，才写成"有效"；否则写"未观察到差异"。

### 实测成本（用于排期，不作为结果）

睡眠语料 4 3656 训练 / 7 150 验证窗口，2 通道、dim 64、batch 64、8 线程 CPU：

| 项 | 实测 |
|---|---|
| 每次运行的固定开销（扫训练集拟合归一化统计） | **290 s** |
| 1 epoch（682 步训练 + 112 步验证） | **202 s** |
| 单次 1 epoch 冒烟总耗时 | 493 s |
| 30 epoch 的被试分组 5 折推算 | ≈ 9 h（5 × 1.8 h） |
| 30 epoch 的被试分组 10 折推算 | ≈ 18 h |

因此睡眠侧不做留一法（100 名被试 = 100 折，约 180 h），改用被试分组 5–10 折。
另：单轮冒烟在验证集上得到 subject-macro BA 0.639，**这只是一个"管线能跑通"的信号**，
未调参、未多种子、单一划分，不能作为结果引用。
