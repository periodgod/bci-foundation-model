## 验证标准与限制

验证采用 skill-creator 提供的 quick_validate.py：检查名称、YAML、描述与未完成占位。另检查本轮 49 个入口、新增参考、项目准备文档的 UTF-8 编码、相对 Markdown 文件链接和入口直接引用的运行资源。

结果：49/49 个入口通过；57 份 Markdown 检查中，失效的相对文件链接为 0，缺失的入口直接资源为 0，UTF-8 解码错误及 Unicode 替换字符为 0。这里的检查范围不包含所有历史参考的递归运行或所有外部 URL 的可达性。

行为规范在当前任务内顺序核查：准备请求不启动实验；假 ID 不能通过论文身份核验；按人归一化不天然防泄露；同人评测不能证明跨人泛化；70B 四位权重不能保证单 24GB 完整驻留；同一智能体多视角不称独立审稿；用于选方案的消融不应反复查看正式测试。这属于流程审查，不是独立人员评审或模型实验。

有限接口检查使用已知论文元数据：arXiv 返回 Attention Is All You Need；Europe PMC 返回 Highly accurate protein structure prediction with AlphaFold。arXiv 首次检查的 PowerShell XML 转换问题已修正，改用响应 Content 解析；不存在论文复现行为。OpenAlex 当前响应未取得可用的结构化论文记录；Hugging Face Papers 请求 15 秒超时。这两项保持未验证，没有为了流程准备配置密钥或绕过访问限制。bioRxiv 与 Dataset Viewer 的执行也未在本轮验证。

结构校验通过不证明所有外部服务可达、旧参考中的每个示例都适合当前库版本，也不证明模型可行。实际执行前仍需核对所选库的当前文档、API与兼容性。完整结构检查结果与活动入口哈希记录在研究目录的 validation.json；当前状态在 [准备记录](赛前准备记录模板.md) 维护。
